# Спек: редизайн фильтр-панели → горизонтальный toolbar + popup

**Дата:** 2026-05-20.
**Статус:** утверждён в брейншторминге, ждёт плана реализации.
**Эпик:** часть итерации C (`v1.0.3`). Заменяет вертикальную фильтр-панель в левой колонке `MainWindow`, заведённую в Task 7.

## Контекст

Итерация C ввела четыре новых критерия фильтрации (поиск, жанр уже были; добавились min рейтинг, реакция, теги). Все они были сложены в левую колонку под существующий поиск и фильтр по жанру. По факту:

- В дефолтном окне (760 px высоты) левая колонка съедает ~440 px на фильтры, на список треков остаётся ~210 px — видно только **4 трека**.
- Слайдер рейтинга визуально не вписался в палитру (по фидбеку пользователя — «блевотный»).
- Кнопка ↻ и кнопки реакции/звёзд были слишком мелкими для клика.
- Тег-чипы хорошие, но всё вместе создаёт ощущение «перегруженного» интерфейса.

По результатам брейншторминга пользователь подтвердил приоритеты:

- **Часто используемые фильтры:** поиск, жанр, теги.
- **Редко используемые:** min рейтинг, реакция.

Решение — разделить эти два уровня визуально и убрать редкие фильтры из основного экрана.

## Цель

1. Освободить левую колонку под список треков. Цель: ≥7 видимых треков на дефолтном размере окна.
2. Дать тегам, поиску и жанру равноправное место «всегда на виду».
3. Убрать рейтинг/реакцию в popup за иконкой ⋮ — они доступны в один клик, но не отнимают пиксели когда не нужны.
4. Сохранить визуальный язык: золото `#D4A574` для активного, тёмная палитра, фирменные шрифты.
5. Сохранить unit-тестируемость через существующий `LibraryFilter` — pure-функция и её `LibraryFilterCriteria` не меняются. Меняется только Presentation-слой и часть `MainViewModel`-команд / биндингов.

## Toolbar

**Высота:** ~52 px (один ряд).
**Размещение:** между брендовым header (`Grid.Row=0`) и колонками (`Grid.Row=1`). Добавляется новая `Grid.Row` высотой `Auto`.
**Фон:** `#4D16161F` (как левая колонка сейчас), `BorderBrush="{StaticResource GoldBorderBrush}"` снизу 1 px.

### Содержимое (слева направо)

1. **Поле поиска** (flex 1, мин 200 px).
   - `Style="{StaticResource SearchTextBoxStyle}"`.
   - Внутри плейсхолдер `Tag="Название, исполнитель, альбом, жанр…   (Ctrl+F)"`.
   - Биндинг `SearchText` с `Delay=250` — без изменений.
   - Имя элемента `SearchBox` сохраняется (на нём завязан `OnFindCommandExecuted`).
2. **Жанр** — `ComboBox` со `Style="{StaticResource GenreComboBoxStyle}"`, ширина ~150 px, биндинг `SelectedGenre`. Без изменений.
3. **Тег-чипы** (flex 1). См. раздел «Тег-чипы и overflow».
4. **Иконка ⋮** — кнопка popup. См. раздел «Popup ⋮».

Внутренние отступы: 16 px по горизонтали между группами; padding контейнера 14 px по вертикали, 18 px по горизонтали.

## Тег-чипы и overflow

Контейнер — кастомный `ItemsControl` поверх `Canvas`/`StackPanel`. Логика overflow реализуется через measure-pass в code-behind контейнера:

- На каждый layout-pass контейнер прогоняет видимые чипы по ширине, накапливая ширину. Те, что помещаются вместе с пилюлей «+ N ещё», остаются `Visibility=Visible`. Те, что не влезли, → `Collapsed`.
- Пилюля «+ N ещё ▾» появляется, когда количество скрытых чипов > 0. Внутри текста — реальное число скрытых.
- По клику на пилюлю открывается `Popup` (см. ниже).

Каждый чип — `Border` с биндингом на `TagFilterItem` (уже существует). При клике — `ToggleTagFilterCommand` (уже существует). Активный чип: золотой фон `#33D4A574` + рамка `PrimaryBrush`. Неактивный: фон `#2616161F` + рамка `#D4A57440`.

### Popup «+ N ещё»

- Привязан к пилюле (`PlacementTarget`), `Placement=Bottom`, `StaysOpen=False` (closes on click outside).
- Внутри — вертикальный `ItemsControl` со скрытыми чипами в `Wrap`-панели (или просто столбец, если width > 200 px). Клик переключает выделение через тот же `ToggleTagFilterCommand`. Popup НЕ закрывается на клик чипа — пользователь может пометить несколько.
- Внизу popup-а — текстовая ссылка «Обновить список» (вызывает `RefreshTagFiltersCommand`). Без иконки ↻, просто текст.

**Ограничение скоупа:** автоматический refresh тегов при их изменении в `TagsWindow` — отдельный refactor (event-based, через `IObservable`/`INotifyTagListChanged`-pattern). В этом спеке — пока ручная ссылка.

## Popup ⋮

Открывается по клику на иконку `⋮` справа в toolbar. `Placement=Bottom`, `StaysOpen=False`, ширина ~280 px.

Содержимое (сверху вниз):

1. **«Минимальный рейтинг»** — заголовок `MutedForegroundBrush`, размер 12.
   - Ряд: пилюля **«Все»** + пять **★** размером 24 px.
   - Пилюля «Все» активна когда `MinRating == 0`; звезда N активна когда `MinRating >= N`.
   - Клик «Все» → `MinRating = 0`. Клик звезды N → `MinRating = N`. Клик горящей звезды N → `MinRating = 0` (toggle-to-clear).
   - Visual: активные используют `RatingThresholdToBrushConverter` (уже есть). Активная пилюля «Все» использует новый минимальный конвертер `ZeroAsActiveBrushConverter` или inline `DataTrigger Binding=MinRating Value=0`.
2. **«Реакция»** — заголовок аналогично.
   - Три кнопки в ряд: `[Все]` (текст), `[♥]` (красный когда `Liked` активен), `[♥̶]` (тёмно-серый когда `Disliked` активен).
   - Используют существующие конвертеры `ReactionMatchToBrushConverter`, `LikeReactionToBrushConverter`, `DislikeReactionToBrushConverter` — менять не нужно.
   - Padding кнопок 6×14, размер глифов 18 px. Сейчас в фильтр-панели они были 11 px — мелко.
3. **Полоса-кнопка «Сбросить все фильтры»** на всю ширину popup-а — золотая рамка + золотой текст. По клику — `ClearFiltersCommand` (уже есть).

## ViewModel-изменения (минимум)

- Все команды и свойства уже существуют после Task 7 (`MinRating`, `ReactionFilter`, `SelectedTagIds`, `TagFilters`, `ToggleTagFilterCommand`, `SetReactionFilterCommand`, `ClearFiltersCommand`, `RefreshTagFiltersCommand`).
- **Меняется только XAML-привязка** — переезд из левой колонки в новую `Grid.Row` toolbar-а.
- **Удаляется** старая разметка фильтр-секции в левой колонке.
- Возможно понадобится новый `bool ShowMoreHiddenTagsCount` или `int HiddenTagsCount` — рассчитывается из measure-pass контейнера (можно сделать в code-behind, не VM).

## Архитектурные инварианты, которые сохраняются

- `LibraryFilter` и `LibraryFilterCriteria` не меняются — это pure-функция, спецификация фильтров не зависит от UI.
- `ApplyFilters()` логика в `MainViewModel` не меняется — она уже собирает criteria из VM-свойств.
- Конвертеры (`RatingThresholdToBrushConverter`, `ReactionMatchToBrushConverter`, `Like/DislikeReactionToBrushConverter`) переиспользуются.
- Стили `SearchTextBoxStyle`, `GenreComboBoxStyle`, `TagChipStyle` переиспользуются.

## Тестирование

- Unit-тесты на `LibraryFilter` (10 шт.) — не трогаем, они валидны.
- Unit-тесты на VM-команды (`SetRatingCommand`, `ToggleTagFilter`, и т.д.) — валидны.
- Дополнительно: можно добавить smoke-тест `TagOverflowContainer_Hides_Chips_That_Dont_Fit` для нового контейнера, если выделим его как самостоятельный контрол с тестируемой логикой.

Ручная проверка после реализации:

- Дефолтный размер окна → видно ≥7 треков.
- Поиск + жанр + 2 тега + min рейтинг через popup → корректное пересечение, порядок по `bm25`.
- Открыть popup ⋮, накликать звёзды → значение обновляется, при клике на горящую звезду сбрасывается в «Все».
- Кнопка «Сбросить все фильтры» очищает всё разом.
- Создать 10+ тегов в TagsWindow → нажать «Обновить список» в popup-е тегов → видно новые. Часть тегов скрыта за «+ N ещё ▾», по клику открывается popup с остальными.
- При уменьшении ширины окна теги уходят за «+ N ещё» автоматически (measure-pass работает).

## Сознательные ограничения скоупа

- Pinned-теги (вариант 3 из брейншторма) — отвергнут. Тег нельзя пометить «любимым» в этой версии.
- Horizontal scroll со стрелками ←/→ для тегов — отвергнут.
- Автоматический refresh тегов при изменениях в TagsWindow — отложен до отдельной задачи (`event-based` paradigm подразумевает либо `IObservable<...>` подписку на репозиторий, либо явный `INotifyTagListChanged` сервис, либо WPF messenger pattern — выбор архитектуры — задача 1.0.4+).
- Адаптивная вёрстка для узких окон — мин. ширина окна остаётся 980 px (как сейчас), при ширине меньше поведение не оптимизируется. Toolbar просто прижимает пилюлю «+ N ещё» сильнее.

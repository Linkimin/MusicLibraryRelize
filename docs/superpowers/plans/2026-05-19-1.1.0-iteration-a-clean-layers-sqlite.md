# MusicBakh 1.1.0 — Итерация A: чистые слои + SQLite-репозитории

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Заменить JSON-индекс библиотеки и истории прослушиваний на SQLite (через EF Core), одновременно разнести код по слоям (`Core` / `Application` / `Infrastructure` / `Presentation.Wpf`) и завести DI-контейнер. Поведение для пользователя не меняется — это рефакторинг, который готовит почву для всех следующих итераций фазы A и фазы B.

**Architecture:** Доменные модели и репозиторий-абстракции переезжают в `MusicBakh.Core`. Use-case-абстракции (метаданные, обложки, импорт, диалоги) переезжают в `MusicBakh.Application`. Реализации (SQLite-репозитории, HTTP-клиенты MusicBrainz/iTunes, FileService, TagLibSharp-обёртка, миграция данных) переезжают в `MusicBakh.Infrastructure`. WPF-проект `MusicLibrary` остаётся презентационным слоем и собирает зависимости через `Microsoft.Extensions.DependencyInjection` в `App.xaml.cs`. SQLite-схема ведётся EF Core миграциями. При первом запуске сервис миграции читает `userTracks.json`, переливает в SQLite, переименовывает старый файл в `userTracks.json.backup-{timestamp}`.

**Tech Stack:** .NET 10 (`net10.0-windows` для WPF, `net10.0` для библиотек), C# 14, EF Core 10 SQLite, `Microsoft.Extensions.DependencyInjection` + `Microsoft.Extensions.Hosting`, xUnit (как в существующем тест-проекте), Serilog (опционально к этой итерации — формально внедряется в `1.8.0`).

**Совместимость данных:** старый `userTracks.json` после миграции сохраняется как `userTracks.json.backup-{yyyyMMdd-HHmmss}` в той же папке. SQLite-файл живёт в `%LocalAppData%\MusicLibrary\library.db`. Это позволяет пользователю откатиться на `1.0.0`, если что-то пойдёт не так — приложение `1.0.0` при отсутствии `userTracks.json` начнёт с пустой пользовательской библиотеки, но переименованный `.backup` файл можно вернуть руками.

**Постусловие итерации:**
- В `MusicLibrary` нет ни одного `using MusicLibrary.Services.Storage`/`Tracks`/`Metadata`/`Covers`/`Files`/`Playback`/`Import` кроме `MainWindow.xaml.cs` / `App.xaml.cs` (всё через DI).
- `userTracks.json` больше не читается и не пишется при штатной работе.
- `MusicLibrary.Tests` проходит зелёным, плюс добавлено покрытие SQLite-репозиториев и сервиса миграции.
- Десктоп запускается на чистой машине **и** на машине с существующим `userTracks.json` (от релиза `1.0.0`) — оба сценария ведут к одинаковому состоянию библиотеки.

- [ ] **Step 7: Адаптировать `InMemoryTrackRepository` и `CompositeTrackRepository`**

`InMemoryTrackRepository` сейчас возвращает встроенные треки. Реализуем новый расширенный интерфейс — добавление/удаление бросают `NotSupportedException` (это seed-репозиторий).

`MusicLibrary/Services/Tracks/InMemoryTrackRepository.cs`:

```csharp
using MusicBakh.Core.Abstractions;
using MusicBakh.Core.Domain;

namespace MusicLibrary.Services.Tracks;

public sealed class InMemoryTrackRepository : ITrackRepository
{
    private readonly IReadOnlyList<Track> _tracks;

    public InMemoryTrackRepository()
    {
        // существующий seed остаётся как было
        _tracks = SeedTracks.BuildDefault();
    }

    public IReadOnlyList<Track> GetAll() => _tracks;

    public Track? FindById(int id) => _tracks.FirstOrDefault(t => t.Id == id);

    public Track Add(Track track) =>
        throw new NotSupportedException("Seed-репозиторий встроенных треков не поддерживает добавление.");

    public void Remove(int id) =>
        throw new NotSupportedException("Seed-репозиторий встроенных треков не поддерживает удаление.");
}
```

Если в текущем InMemoryTrackRepository seed-данные собираются прямо в конструкторе — вынеси их в `SeedTracks.BuildDefault()` отдельным статическим методом в этом же файле, чтобы было удобно переиспользовать позже.

Аналогично для `CompositeTrackRepository`: метод переименовать `GetTracks` → `GetAll`, `Add` и `Remove` сейчас бросают `NotSupportedException` (мы его в Task 11 заменим на SqliteTrackRepository).

/// <summary>
/// Создаёт LibraryDbContext поверх in-memory SQLite. Соединение должно жить столько же,
/// сколько контекст — иначе SQLite освободит память. Тест отвечает за Dispose.
/// </summary>
internal sealed class InMemorySqliteDbContextFactory : IDisposable
{
    private readonly SqliteConnection _connection;
    private readonly DbContextOptions<LibraryDbContext> _options;

    public InMemorySqliteDbContextFactory()
    {

        _connection.Open();

        _options = new DbContextOptionsBuilder<LibraryDbContext>()
            .UseSqlite(_connection)
            .Options;

        using var ctx = new LibraryDbContext(_options);
        ctx.Database.EnsureCreated();
    }

    public LibraryDbContext CreateContext() => new(_options);

    public void Dispose() => _connection.Dispose();
}

```csharp
using MusicBakh.Core.Abstractions;
using MusicBakh.Core.Domain;
using MusicBakh.Infrastructure.Persistence.Entities;

namespace MusicBakh.Infrastructure.Persistence.Repositories;

/// <summary>
/// Репозиторий треков поверх LibraryDbContext. Получает фабрику контекста, чтобы каждый
/// вызов работал на свежем коротком контексте — это устраняет проблемы с life-time'ом
/// при многопоточности и упрощает тесты.
/// </summary>
public sealed class SqliteTrackRepository : ITrackRepository
{
    private readonly Func<LibraryDbContext> _contextFactory;

    public SqliteTrackRepository(Func<LibraryDbContext> contextFactory)
    {
        _contextFactory = contextFactory;
    }

    public IReadOnlyList<Track> GetAll()
    {
        using var ctx = _contextFactory();
        return ctx.Tracks
            .OrderBy(t => t.IsBuiltIn ? 0 : 1)
            .ThenBy(t => t.Id)
            .Select(MapToDomain)
            .ToList();
    }

    public Track? FindById(int id)
    {
        using var ctx = _contextFactory();
        var entity = ctx.Tracks.FirstOrDefault(t => t.Id == id);
        return entity is null ? null : MapToDomain(entity);
    }

    public Track Add(Track track)
    {
        using var ctx = _contextFactory();
        var entity = new TrackEntity
        {
            Title = track.Title,
            Artist = track.Artist,
            Genre = track.Genre,
            DurationTicks = track.Duration.Ticks,
            FilePath = track.FilePath,
            CoverPath = track.CoverPath,
            AddedAtUtc = DateTime.UtcNow,
            IsBuiltIn = false
        };
        ctx.Tracks.Add(entity);
        ctx.SaveChanges();

        return MapToDomain(entity);
    }

    public void Remove(int id)
    {
        using var ctx = _contextFactory();
        var entity = ctx.Tracks.FirstOrDefault(t => t.Id == id);
        if (entity is null)
        {
            return;
        }
        ctx.Tracks.Remove(entity);
        ctx.SaveChanges();
    }

    private static Track MapToDomain(TrackEntity e) => new()
    {
        Id = e.Id,
        Title = e.Title,
        Artist = e.Artist,
        Genre = e.Genre,
        Duration = TimeSpan.FromTicks(e.DurationTicks),
        FilePath = e.FilePath,
        CoverPath = e.CoverPath
    };
}
```

**Замечание:** `Add` сейчас вызывает `DateTime.UtcNow` напрямую — это нарушает тестируемость. Это сознательный компромисс: для треков `AddedAtUtc` пока не используется ни в одном тесте, а вытаскивание `IClock` через все слои на этой итерации даст шум без пользы. Для `IListeningHistoryRepository` (Task 11) `IClock` уже **обязателен**, потому что `PlayedAt` участвует в утверждениях тестов.

```csharp
using System.Globalization;
using MusicBakh.Core.Abstractions;
using MusicBakh.Core.Domain;
using MusicBakh.Infrastructure.Persistence.Entities;

namespace MusicBakh.Infrastructure.Persistence.Repositories;

public sealed class SqlitePlayerSettingsRepository : IPlayerSettingsRepository
{
    private const string VolumeKey = "player.volume";
    private const string IsMutedKey = "player.isMuted";
    private const string RepeatModeKey = "player.repeatMode";

    private readonly Func<LibraryDbContext> _contextFactory;

    public SqlitePlayerSettingsRepository(Func<LibraryDbContext> contextFactory)
    {
        _contextFactory = contextFactory;
    }

    public PlayerSettings Load()
    {
        using var ctx = _contextFactory();
        var entries = ctx.KeyValueStore.ToDictionary(k => k.Key, k => k.Value);

        return new PlayerSettings(
            Volume: ReadDouble(entries, VolumeKey, PlayerSettings.Default.Volume),
            IsMuted: ReadBool(entries, IsMutedKey, PlayerSettings.Default.IsMuted),
            RepeatMode: ReadEnum(entries, RepeatModeKey, PlayerSettings.Default.RepeatMode));
    }

    public void Save(PlayerSettings settings)
    {
        using var ctx = _contextFactory();
        Upsert(ctx, VolumeKey, settings.Volume.ToString(CultureInfo.InvariantCulture));
        Upsert(ctx, IsMutedKey, settings.IsMuted ? "true" : "false");
        Upsert(ctx, RepeatModeKey, settings.RepeatMode.ToString());
        ctx.SaveChanges();
    }

    private static void Upsert(LibraryDbContext ctx, string key, string value)
    {
        var existing = ctx.KeyValueStore.FirstOrDefault(k => k.Key == key);
        if (existing is null)
        {
            ctx.KeyValueStore.Add(new KeyValueEntryEntity { Key = key, Value = value });
        }
        else
        {
            existing.Value = value;
        }
    }

    private static double ReadDouble(IDictionary<string, string> map, string key, double fallback) =>
        map.TryGetValue(key, out var raw) && double.TryParse(raw, NumberStyles.Float, CultureInfo.InvariantCulture, out var v)
            ? v : fallback;

    private static bool ReadBool(IDictionary<string, string> map, string key, bool fallback) =>
        map.TryGetValue(key, out var raw) && bool.TryParse(raw, out var v) ? v : fallback;

    private static RepeatMode ReadEnum(IDictionary<string, string> map, string key, RepeatMode fallback) =>
        map.TryGetValue(key, out var raw) && Enum.TryParse<RepeatMode>(raw, out var v) ? v : fallback;
}
```

**Спорные места, на которые следует обратить внимание при исполнении:**

- В Task 14 я предложил конвертировать `Track` в `record`, чтобы работал `with`-expression. Это вторгается в Task 2, где `Track` копируется из существующего кода. Если решите оставить `class`, замените `_repository.Add(t with { IsBuiltIn = true })` на явное копирование через `new Track { ... IsBuiltIn = true }`.
- `TrackImporter` сейчас принимает `IUserTrackStorage` — это значит, что после Task 15 он перестаёт собирать пользовательские записи в JSON и начинает писать в `ITrackRepository`. **Это поведенческое изменение, скрытое в рефакторинге.** Smoke-test (Task 17) ловит это, но я рекомендую перед Task 17 запустить руками сценарий импорта и убедиться, что трек реально появляется в SQLite (`SELECT * FROM Tracks;` через `sqlite3` CLI).
- Версии EF Core (10.0.0) — на момент исполнения проверь актуальный major. Если `.NET 10` ещё не GA или EF 10 не выпущен — используй EF Core 9 с `net10.0` target frameworks (EF 9 совместим).
- `Microsoft.WindowsAPICodePack` или другие win-only зависимости в `FileService` могут потребовать `net10.0-windows` для `MusicBakh.Infrastructure`. Проверь при Task 12; если зависимостей нет — оставь `net10.0`, если есть — поменяй TargetFramework на `net10.0-windows`.

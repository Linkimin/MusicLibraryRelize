# 1.0.4 — Library 2.0, итерация D (альбомные и исполнительские views)

Четвёртая итерация многоэтапной работы «Library 2.0». Библиотека перестаёт быть плоским списком: в шапке появляются три вкладки — **Треки / Альбомы / Исполнители**, с drill-down в детальные страницы альбома и исполнителя. Группировка — computed-агрегаты поверх той же фильтрации, что и раньше (см. [ADR-0001](../adr/0001-album-artist-computed-aggregates.md)).

## Что нового для пользователя

### Три вкладки в шапке

- В центре шапки — три таба «Треки» / «Альбомы» / «Исполнители». Активный подсвечен золотом.
- Переключение мышью или хоткеями **Ctrl+1 / Ctrl+2 / Ctrl+3**.
- При смене вкладки меняется только левая колонка; «Сейчас играет» и «История» справа не двигаются.
- Активная вкладка сохраняется между запусками (ключ `active_view` в `KeyValueStore`).

### Альбомы

- Сетка плиток 3×N: обложка (первого трека альбома), название альбома, «Исполнитель · Год» приглушённо.
- Плитки отсортированы `Year DESC NULLS LAST, Title ASC` — свежие альбомы сверху, альбомы без года в конце.
- Клик по плитке → детальная страница альбома: обложка, метаданные, треклист (сортировка `TrackNumber ASC NULLS LAST, Title ASC`), кнопки **▶ Воспроизвести альбом** и **🔀 Перемешать**. «← Все альбомы» или **Esc** возвращают в сетку.

### Исполнители

- Вертикальный список: круглый аватар с инициалом (детерминированный цвет по имени), имя, «N альбомов · M треков».
- Отсортированы по количеству треков (`Tracks.Count DESC, Name ASC`).
- Клик → страница исполнителя: аватар, счётчики, **▶ Слушать всё** / **🔀 Перемешать** (вся дискография), под-сетка альбомов и секция «Прочие треки» (треки без тега Album). Клик по альбому внутри страницы исполнителя уходит ещё глубже; **Esc** возвращает на страницу исполнителя, следующий **Esc** — на список исполнителей.

### Play / Shuffle для альбома и исполнителя

- **Воспроизвести альбом** заменяет очередь треками альбома в порядке треклиста и стартует первый.
- **Слушать всё** у исполнителя собирает дискографию: альбомы (Year DESC), внутри — по номеру трека, затем прочие треки.
- **Перемешать** играет тот же набор в случайном порядке (Fisher-Yates), без потерь и дублей.

### Фильтры работают и в новых views

- Поиск, жанр, теги, рейтинг, реакция применяются **сначала** к трекам, затем результат группируется в альбомы/исполнителей. Альбом/исполнитель виден, только если после фильтра остался хотя бы один трек. Drill-down уважает активные фильтры.

### Compilations

- Треки с тегом `AlbumArtist` (например, `Various Artists`) группируются в один альбом по ключу `(AlbumArtist, Album)`.
- При этом в списке «Исполнители» каждый исполнитель из сборника виден отдельно со своими треками (ключ группировки — `Track.Artist`, не `AlbumArtist`).

## Хранение данных

- Доменная модель `Track` получила три новых nullable-поля: `Year` (int?), `TrackNumber` (int?), `AlbumArtist` (string?). Старые треки получают `NULL` до следующего ре-импорта.
- EF Core миграция `AddTrackYearNumberAlbumArtist` — три nullable-колонки + индекс на `Year`. Применяется автоматически при первом запуске, данные не теряются.
- Импорт нового трека читает эти поля из ID3 (`tag.Year`, `tag.Track`, `tag.FirstAlbumArtist`; значение 0 у Year/Track → NULL).

## Внутренние изменения

- Новый pure-function слой группировки: `LibraryGroupingService.GroupByAlbum/GroupByArtist` (`MusicLibrary/Services/Library/`) поверх результата `LibraryFilter` — те же фильтры, потом группировка.
- Новые computed-агрегаты: `AlbumAggregate` (Title, Artist=`AlbumArtist ?? Artist`, Year, CoverPath, Tracks, TotalDuration, AlbumKey) и `ArtistAggregate` (Name, Albums, LooseTracks, TotalTracks, TotalDuration). `AlbumKey` использует разделитель `U+001F` (Unit Separator) между Artist и Title, чтобы drill-down-идентификатор не коллизировал.
- Состояние view: enum `MainViewMode` (в `MusicBakh.Core.Domain`), `LeftColumnState` (abstract record с вариантами TracksRoot/AlbumsRoot/ArtistsRoot/AlbumDetail/ArtistDetail) и back-стек в `MainViewModel`. Асимметрия «Исполнитель→Альбом→Back возвращает на исполнителя» реализована порядком в стеке.
- Новые команды `MainViewModel`: `SwitchViewCommand`, `OpenAlbumCommand`, `OpenArtistCommand`, `BackCommand`, `PlayAlbumCommand`, `ShuffleAlbumCommand`, `PlayArtistCommand`, `ShuffleArtistCommand`.
- Левая колонка — `ContentControl` с `LeftColumnTemplateSelector` (`MusicLibrary/Selectors/`), пять DataTemplates в `MusicLibrary/Resources/AlbumsArtistsTemplates.xaml`, стиль вкладок — `MainViewTabsStyles.xaml`.

## Сборка и зависимости

- Устранён свежий high-severity advisory **NU1903** (GHSA-2m69-gcr7-jv3q) на транзитивный `SQLitePCLRaw.lib.e_sqlite3 2.1.11`: явный пин `SQLitePCLRaw.bundle_e_sqlite3 3.0.3`, EF Core `10.0.8 → 10.0.9` согласованно. Регрессии по SQLite нет (полный round-trip + FTS5 + миграции зелёные).

## Тесты

- **242 теста** проходят (было 213 в `1.0.3`) + 1 бенчмарк под трейтом `Category=Benchmark`. Новые блоки:
  - `LibraryGroupingServiceTests` — группировка по альбомам/исполнителям, сортировки NULLS LAST, compilations, collision-safe `AlbumKey`, loose-track правило.
  - `MainViewModelNavigationTests` — переключение вкладок, back-стек (включая Артист→Альбом→Back асимметрию), порядок очереди Play-album/Play-artist, сохранность набора при Shuffle.
  - round-trip тесты новых полей `Track` в `SqliteTrackRepositoryTests`, проброс полей в `DefaultMetadataResolverTests`.
- Бенчмарк FTS на 50 000 треков сохраняет результат < 100 мс — не просел.

## Сознательные ограничения (см. `scope-deviations.md` §1.0.4)

- **Compilations** работают только если в тегах заполнен `AlbumArtist`. Файлы без этого тега — каждый исполнитель сам по себе.
- **Биография и обложка исполнителя** не показываются — только круглый аватар с инициалом. Отложено до `1.3.0` (Metadata & Lyrics).
- **Play-album / Play-artist переписывают `DisplayedTracks`**, временно игнорируя активный фильтр. Полная разгрузка — `1.0.5+`.
- **Без виртуализации** в Albums/Artists views (встроенной WPF-виртуализации хватает на текущих объёмах).
- **Без context-menus и drag-and-drop** в новых views.
- **Дубликаты альбомов** из-за расхождений в написании тегов остаются — ручное слияние отложено (см. ADR-0001).

## Что НЕ изменилось для пользователя

- Воспроизведение, импорт, удаление, рейтинги/реакции/теги (1.0.3), поиск и фильтр-toolbar, экран статистики, история — поведение и UI совпадают с `1.0.3`. Вкладка «Треки» рендерит тот же список, что и раньше.

# 1.1.0 — Library 2.0 (в разработке)

Минор `1.1.0` посвящён полному переустройству хранения и архитектуры приложения. Большая часть пользовательских фич минора (умные плейлисты, рейтинги, теги-ярлыки, watched folders, FTS5-поиск, multi-column sort и др.) добавляется в последующих итерациях B–H. Итерация A — техническая и закладывает фундамент.

## Iteration A — Чистые слои + SQLite-репозитории

### Архитектура
- BREAKING (internal): монолитный WPF-проект разделён на 4 проекта:
  - `MusicBakh.Core` — доменные модели и репозиторий-абстракции (`net10.0`).
  - `MusicBakh.Application` — use-case-абстракции и контракты (`net10.0`).
  - `MusicBakh.Infrastructure` — SQLite поверх EF Core, HTTP-клиенты (MusicBrainz, iTunes), теггер TagLibSharp, файловая система, сервис миграции, seed (`net10.0`).
  - `MusicLibrary` — WPF-презентация: ViewModels, Views, WPF-зависимые сервисы (`MediaPlayerAudioService`, `ProceduralCoverGenerator`, файловые диалоги). Остался `net10.0-windows`.
- DI-композиция через `Microsoft.Extensions.Hosting` в `App.OnStartup`, заменяет ручную сборку в `MainWindow.xaml.cs:20`.
- ServiceCollection-расширения `AddMusicBakhInfrastructure` и `AddMusicBakhPresentation` инкапсулируют регистрацию сервисов своего слоя.

### Хранение данных
- BREAKING (data): пользовательская библиотека переехала с `userTracks.json` на SQLite (`%LocalAppData%\MusicLibrary\library.db`). Схема ведётся EF Core миграциями:
  - `AddLibrarySchema` — таблица `Tracks`.
  - `AddListeningHistory` — таблица `ListeningHistory` с FK на `Tracks`.
  - `AddKeyValueStore` — таблица `KeyValueStore` для настроек плеера.
- При первом запуске после апгрейда с 1.0.x `JsonToSqliteMigrationService` автоматически переносит записи из `userTracks.json` в SQLite и переименовывает старый файл в `userTracks.json.backup-<timestamp>`. Сервис идемпотентен: повторный запуск ничего не делает.
- История прослушиваний и настройки плеера (громкость, mute, режим повтора) теперь тоже в SQLite — раньше история жила только в памяти, а настройки — в `player-settings.json`.

### Внутренние изменения
- Доменная модель `Track` обзавелась флагом `IsBuiltIn`, отделяющим встроенные seed-треки от пользовательских. Удаление встроенных запрещено и в UI (`CanDeleteSelected`), и в `SqliteTrackRepository` (через флаг).
- `BuiltInTrackSeeder` наполняет пустую БД тремя эталонными треками при первом запуске. Единый источник правды — `BuiltInTracksProvider.GetDefaults`.
- Новая абстракция `IClock` (реализация `SystemClock`) позволяет тестам зафиксировать время для `SqliteListeningHistoryRepository`.
- Новая абстракция `IMusicStoragePaths` (реализация `LocalAppDataMusicStoragePaths`) заменяет утечку путей через `IUserTrackStorage` — `TrackImporter` теперь зависит только от путей, не от хранилища.
- `IFileService.Delete` добавлен — `MainViewModel` теперь сам убирает аудио- и кавер-файлы при удалении пользовательского трека.

### Что НЕ изменилось для пользователя
В итерации A сознательно нет новых видимых фич — это чисто архитектурная перековка перед итерациями B (FTS5 + extended history), C (рейтинги + лайки + теги), D (album/artist views), E (статические плейлисты), F (умные плейлисты), G (watched folders), H (multi-column sort).

После запуска пользователь должен увидеть **ровно тот же UX**, что и в `1.0.0`, но:
- запуск может стать заметно быстрее на больших библиотеках за счёт FTS5 и индексированных запросов (видно начиная с итерации B);
- архитектура готова к появлению backend в фазе B (`2.0.0`).

# 1.0.2 — Library 2.0, итерация B (FTS5-поиск + расширенная история)

Вторая итерация многоэтапной работы «Library 2.0». В отличие от технической итерации A (`1.0.1`), здесь появляются первые видимые пользователю фичи: поле поиска и экран статистики прослушиваний.

## Что нового для пользователя

### Поиск по библиотеке
- Над фильтром по жанру появилось поле «Поиск». Ввод фильтрует список треков по `Title` / `Artist` / `Album` / `Genre` в реальном времени (дебаунс ~250 мс).
- Поиск и фильтр по жанру совмещаются: поиск даёт кандидатов, жанр оставляет из них только нужные.
- Хоткей **Ctrl+F** фокусирует поле из любой точки окна и выделяет текущий текст. **Esc** очищает поле и снимает фокус.
- Под капотом — SQLite FTS5 с токенизатором `unicode61 remove_diacritics 2`: «Café» находится по «cafe», «Mötley» по «motley». На библиотеке ~50 тыс. треков средний поиск укладывается в ~10 мс на dev-машине (бюджет роадмапа — 100 мс).

### Экран статистики прослушиваний
- В шапке появилась кнопка **«Статистика»** (хоткей **Ctrl+T**). Открывает отдельное окно с тремя вкладками:
  - **Топ-50** — самые прослушиваемые треки за всё время с количеством прослушиваний.
  - **Недавние** — последние 50 уникальных треков по времени последнего прослушивания.
  - **Ни разу не играли** — треки библиотеки без записей в истории.
- Каждая вкладка пустая → показывает осмысленное empty-state сообщение.
- Окно не модальное (не блокирует основное), закрывается **Esc**.

### Хоткеи, переработанные под русскую раскладку
- Голые хоткеи `M` / `R` перевешены на **Ctrl+M** / **Ctrl+R** — иначе в русской раскладке клавиши `R`=«К» и `M`=«Ь» переключали повтор/mute вместо ввода буквы в поле поиска.
- Голые стрелки `←`/`→` (skip ±10 с) убраны — их перехватывал ListBox/Slider. Перемотка теперь на **Shift+←/→**.
- `Ctrl+←/→` (предыдущий/следующий трек) и `Ctrl+F` без изменений.

### Прочее
- Если эталонные треки переехали в другую сборочную папку (`bin/Debug` → `bin/Release`), `BuiltInTrackSeeder` теперь обновляет устаревшие `FilePath`/`CoverPath` вместо того, чтобы оставлять «файл не найден».

## Хранение данных

- Доменная модель `Track` обзавелась полем `Album` (опциональное, default `""`). Читается из ID3-тега при импорте; UI группировки по альбомам — итерация D.
- Две новых EF Core миграции:
  - `AddTrackAlbum` — колонка `Album TEXT NOT NULL DEFAULT ''` + индекс.
  - `AddTracksFts` — виртуальная таблица `TracksFts USING fts5(Title, Artist, Album, Genre, content='Tracks')`, три триггера синхронизации (`Tracks_ai`, `Tracks_ad`, `Tracks_au AFTER UPDATE OF Title,Artist,Album,Genre`) и backfill уже существующих треков.
- Миграции применяются автоматически при первом запуске; данные пользователя не теряются.

## Внутренние изменения

- Новый Core-интерфейс `ISearchService` (`MusicBakh.Core.Abstractions`) с одним методом `Search(query, limit) → IReadOnlyList<Track>`. Реализация `SqliteFtsSearchService` — прямой SQL `JOIN TracksFts MATCH ... ORDER BY bm25` через `FromSqlInterpolated`.
- `FtsQueryBuilder` (internal в `MusicBakh.Infrastructure.Search`) превращает свободную пользовательскую строку в безопасный FTS-запрос: чистит зарезервированные символы (`" * : ( )`), оборачивает каждое слово в кавычки + `*` (prefix-match), склеивает через пробел (неявный AND), режет на 10 токенов.
- `IListeningHistoryRepository` расширен четырьмя методами: `GetAll`, `GetTop(limit) → ListeningStats`, `GetRecentUnique(limit)`, `GetNeverPlayed()`. Старый `GetRecent(50)` остаётся для виджета «недавнее» в правой колонке `MainWindow`.
- Новый record `ListeningStats(Track, PlayCount, LastPlayedUtc)` — DTO для топа.
- `ITrackRepository.Update(Track)` — добавлен ради `BuiltInTrackSeeder`-логики «обновить устаревшие пути seed-треков».
- `ITrackRepository.Remove` теперь действительно бросает `NotSupportedException` для встроенных треков (контракт уже это обещал в 1.0.1, но реализация молча удаляла — pre-task исправил).
- `MainViewModel`: `SearchText`-property, синхронный `ApplyFilters()` (in-memory пересечение результатов поиска и фильтра по жанру), `OpenStatsCommand`. Опциональные конструкторные параметры `ISearchService?` и `IStatsWindowService?` для совместимости с существующими unit-тестами.

## Тесты
- 169 проходят (было 130 в `1.0.1`). Новые блоки:
  - `SqliteTrackRepositoryTests` — 3 теста на Remove-контракт.
  - `FtsQueryBuilderTests` — 8 тестов (пустые / спецсимволы / cyrillic / cap / injection).
  - `SqliteFtsSearchServiceTests` — 12 интеграционных тестов поверх миграционной in-memory фикстуры (`MigratedSqliteDbContextFactory`): exact / prefix / multiword AND / Tracks_ai/ad/au триггеры / Latin diacritics / Cyrillic exact / Album-поиск / injection. Один тест меряет `total_changes()` до/после `UPDATE`, чтобы доказать что `AFTER UPDATE OF` clause реально работает.
  - `SqliteListeningHistoryRepositoryTests` — 6 тестов на `GetAll`/`GetTop`/`GetRecentUnique`/`GetNeverPlayed`.
  - `MainViewModelTests` — 4 теста на `SearchText` + комбинация с фильтром по жанру.
  - `BuiltInTrackSeederTests` — 2 теста на refresh устаревших путей.
- Бенчмарк `SqliteFtsSearchServiceBenchmark` (помечен `Trait("Category", "Benchmark")`) сидит 50 000 треков и проверяет средний поиск < 100 мс. Запускается на демонстрационно `--filter "Category=Benchmark"`; обычный `dotnet test --filter "Category!=Benchmark"` его пропускает.

## Сознательные ограничения

- **Без album-view** — поле `Album` есть, UI группировки — итерация D.
- **`й/и` в кириллице не нормализуются** — `unicode61 remove_diacritics 2` обрабатывает только реальную диакритику, а `й` Unicode-классифицирует как отдельную букву. Это известное ограничение SQLite-FTS5, фикс — отдельная задача в backlog `1.0.3+`.
- **`MainViewModel._allTracks` остаётся in-memory копией библиотеки** — пагинация и виртуализация ListBox планируются на итерацию D/E.
- **Use-case-слой остаётся слоем абстракций.** Переезд `MainViewModel`-логики в `*UseCase` / pipeline-handler-ы — ориентир `1.9.0` Architecture hardening.

## Что НЕ изменилось для пользователя

- Воспроизведение, импорт, удаление, форма «Добавить трек», виджет «недавнее» в правой колонке — без изменений (поведение и UI совпадают с `1.0.1`).

# 1.0.3 — Library 2.0, итерация C (рейтинги, лайки, теги-ярлыки)

Третья итерация многоэтапной работы «Library 2.0». Первая итерация с полноценными пользовательскими аннотациями: трекам можно выставлять рейтинг от 0 до 5 звёзд, ставить реакцию «нравится»/«не нравится» и навешивать произвольные теги-ярлыки. Фильтр-панель полностью переработана: вертикальная секция в левой колонке заменена горизонтальным toolbar над списком треков.

## Что нового для пользователя

### Рейтинги 0–5★

- Под обложкой выбранного трека в средней колонке появился ряд из пяти кликабельных звёзд.
- Клик по N-й звезде выставляет рейтинг N. Повторный клик по уже горящей звезде сбрасывает рейтинг до 0.
- Рейтинг сохраняется в базе данных и виден при следующем выборе трека.

### Реакция лайк / дизлайк

- Рядом со звёздами — кнопки реакции: ♥ (лайк, подсвечивается красным в активном состоянии) и ♥̸ (дизлайк, тёмно-серое перечёркнутое сердечко в активном).
- Повторный клик по активной реакции сбрасывает её в «нет реакции».
- Лайк и дизлайк взаимоисключают друг друга.

### Пользовательские теги-ярлыки

- Новое окно «Теги» (**Ctrl+G**): создание, переименование и удаление тегов. Имена тегов уникальны без учёта регистра (кириллица корректно обрабатывается через .NET `OrdinalIgnoreCase`).
- В средней колонке под рейтингом — секция «Теги» с кнопкой «+ тег». Позволяет привязать любой из существующих тегов к текущему треку.
- Прикреплённые теги видны в секции со значком ×, нажатие которого открепляет тег от трека.
- На карточке трека в списке отображается до 3 тег-чипов. Если прикреплено больше 3 тегов — вместо четвёртого и далее появляется золотая пилюля «+N».

### Фильтры по рейтингу, реакции и тегам

- Тег-чипы вынесены прямо в toolbar над списком треков. При переполнении видны первые N чипов, а остальные скрываются за кнопкой «+ N ещё ▾» (кастомный `OverflowChipPanel`).
- За иконкой ⋮ в toolbar скрывается popup с фильтром по рейтингу (ряд звёзд «не ниже N») и по реакции (Лайк / Дизлайк / Нейтральные). Кнопка «Сбросить» в popup очищает оба критерия.
- Все фильтры (поиск, жанр, теги, рейтинг, реакция) работают совместно: на экране остаются только треки, удовлетворяющие всем активным критериям.

### Полный редизайн фильтр-панели

- Вертикальная секция с фильтрами в левой колонке полностью убрана. На её месте — горизонтальный toolbar над списком треков.
- Высота, которую раньше занимал вертикальный фильтр, теперь отдана списку треков: на дефолтном размере окна видно ≥7 треков (ранее было около 4).

## Хранение данных

- Доменная модель `Track` получила два новых поля: `Rating` (int, 0..5, по умолчанию 0) и `Reaction` (enum `TrackReaction`: None / Liked / Disliked, по умолчанию None).
- Добавлены две новые доменные сущности: `Tag` (Id, Name, Color?) и enum `TrackReaction`.
- Три новых EF Core миграции:
  - `AddTrackRatingAndReaction` — колонки `Rating INTEGER NOT NULL DEFAULT 0` и `Reaction INTEGER NOT NULL DEFAULT 0` в таблице `Tracks`.
  - `AddTagsAndTrackTags` — таблица `Tags` (Id, Name, Color) и связующая таблица `TrackTags` с составным PK `(TrackId, TagId)` и каскадным удалением по обоим FK.
- Миграции применяются автоматически при первом запуске; данные пользователя не теряются.

## Внутренние изменения

- Новый Core-интерфейс `ITagRepository` (`MusicBakh.Core.Abstractions`): `GetAll`, `GetByTrackId`, `Add`, `Update`, `Delete`, `AttachToTrack`, `DetachFromTrack`. Реализация `SqliteTagRepository` поверх EF Core. Валидация уникальности имени тега выполняется в коде через .NET `OrdinalIgnoreCase` — SQLite `COLLATE NOCASE` не охватывает кириллицу.
- Новый pure-function слой фильтрации: `LibraryFilter` (статический класс `MusicLibrary/Services/Library/`) + `LibraryFilterCriteria` (record с полями SearchResults, Genre, Tags, MinRating, Reaction). Первый шаг разгрузки `MainViewModel`: фильтр-логика извлечена из VM в самодостаточную, тестируемую функцию.
- Кастомный WPF Panel `OverflowChipPanel` (`MusicLibrary/Controls/`) — измеряет доступную ширину, укладывает чипы слева направо и добавляет пилюлю «+ N ещё ▾» вместо не вместившихся.
- `MainViewModel` обзавёлся `_tagsByTrackId: Dictionary<int, ObservableCollection<Tag>>` — кэш связей тег/трек для биндингов на карточке трека без лишних запросов в БД при прокрутке.
- Команды в `MainViewModel`: `SetRatingCommand`, `SetReactionCommand`, `AttachTagCommand`, `DetachTagCommand`, `OpenTagsWindowCommand`, `SetMinRatingCommand`, `SetReactionFilterCommand`, `ResetRatingReactionFilterCommand`, `ToggleTagFilterCommand`.
- Исправление регрессии итерации B: FTS-поиск теперь возвращает результаты в порядке убывания релевантности (bm25). В 1.0.2 UI сбрасывал порядок при наложении фильтров — устранено.
- Новые WPF-конвертеры: `RatingToStarsConverter`, `ReactionToIconConverter`, `TagsToChipsConverter`, `MinRatingActiveConverter` и другие.

## Тесты

- 213 тестов проходят (было 169 в `1.0.2`). Новые блоки:
  - `SqliteTagRepositoryTests` — 4 теста на attach/detach тегов, уникальность имени.
  - `OverflowChipPanelTests` — 4 теста на измерение и раскладку чипов с overflow.
  - `LibraryFilterTests` — тесты на фильтрацию по рейтингу, реакции и комбинации с поиском/жанром.
  - `MainViewModelTests` — 2 новых теста на `SetMinRatingCommand` + тесты bm25-порядка.
  - Дополнительные тесты на команды SetRating, SetReaction, AttachTag/DetachTag в ViewModel.
- Бенчмарк FTS на 50 000 треков сохраняет результат < 100 мс.

## Сознательные ограничения

- **Pinned-теги не реализованы** — концепция «избранных» тегов была рассмотрена в брейншторминге и отвергнута; в backlog не добавлена.
- **Авто-refresh списка тегов в фильтр-popup** при изменениях в окне «Теги» (TagsWindow) не реализован — при открытии popup список обновляется вручную кнопкой «Обновить список». Event-based подписка отложена в backlog 1.0.4+.
- **Чипы тегов на карточке — snapshot**, не live: добавление тега к треку (в позицию ≥ 4 видимых чипов) не обновит карточку в ListBox до следующего перевыделения трека.
- **Цвет тега** (`Tag.Color`) сохраняется в БД, но визуально на чипах пока не отражается — только в окне «Теги». Можно усилить в 1.0.4.
- **Кириллический case-fold** имён тегов работает через .NET `OrdinalIgnoreCase`, но SQLite-индекс остаётся ASCII-only (`COLLATE NOCASE`). Defence-in-depth на случай гонок.
- **Use-case-слой остаётся слоем абстракций.** Полная разгрузка `MainViewModel` (Playback / History / Deletion / Import) запланирована на итерации 1.0.4–1.0.8, полный переезд — `1.9.0`.

## Что НЕ изменилось для пользователя

- Воспроизведение, импорт, удаление, форма «Добавить трек», виджет «недавнее» в правой колонке, экран статистики, поле поиска и фильтр по жанру — поведение и UI совпадают с `1.0.2`.
